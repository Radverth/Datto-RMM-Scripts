# Warranty Date Sync

Implements the *Warranty Date Sync – Project Plan*: read every active Laptop/Desktop from IT Glue, work out
the correct warranty date (myITProcess vs IT Glue), and write only the changes to IT Glue, Datto RMM and Autotask.

Two implementations share the same rules:

| | Where | Use |
|---|---|---|
| PowerShell | `scripts/Sync-WarrantyDates.ps1` | Run anywhere (scheduled task / Datto component). State in a JSON file. Dry run unless `-Apply`. |
| Power Automate | this folder (`WarrantySync_1_0_0_11.zip`, `flow-expressions.md`, `sharepoint-list.md`) | Plan's target design. State in a SharePoint list. |

## Date rules
| Situation | Result |
|---|---|
| myITProcess blank | keep IT Glue date |
| IT Glue blank or earlier than myITProcess | use myITProcess, write to IT Glue |
| IT Glue later | keep IT Glue, status `Glue later - review` |
| differs from `PushedDate` | write to Datto RMM + Autotask |
| `rmm-id`/`psa-id` missing | skip that system, status `Missing ID` |

`PushedDate` is only set when every write succeeded, so failures retry next run.

## PowerShell quick start
```powershell
# prerequisites: IT Glue type/status IDs + exact myITProcess attribute name (see plan, step 1)
$env:ITGLUE_API_KEY="..."; $env:DATTO_API_URL="https://<platform>-api.centrastage.net"
$env:DATTO_API_KEY="..."; $env:DATTO_API_SECRET="..."
$env:AUTOTASK_BASE_URI="https://webservices5.autotask.net/ATServicesRest/V1.0"
$env:AUTOTASK_USERNAME="..."; $env:AUTOTASK_SECRET="..."; $env:AUTOTASK_INTEGRATION_CODE="..."

.\scripts\Sync-WarrantyDates.ps1 -LaptopTypeId 111 -DesktopTypeId 222 -ActiveStatusId 3 -MyITProcessAttribute "<attr>"          # dry run
.\scripts\Sync-WarrantyDates.ps1 ... -Apply -MaxWritesPerRun 25      # pilot
.\scripts\Sync-WarrantyDates.ps1 ... -Apply                          # backfill (cap 1500/run)
```
Rule tests: `pwsh ./scripts/Sync-WarrantyDates.Tests.ps1`.

Rollout follows plan section 5: dry run for a week, pilot at 25, then cut over and decommission ScalePad.

## Import the Power Automate solution

`WarrantySync_1_0_0_11.zip` (generated by `build/build_solution.py`; source in `solution/`) contains:

- **Warranty Sync - Nightly** flow (imported switched off)
- **Warranty Sync - Autotask Only** and **Warranty Sync - Datto RMM Only** flows (manual trigger), see below
- **Warranty Sync - List Devices** flow (manual trigger, read-only), see below
- Three custom connectors, so no API credentials are stored in the flow or in environment variables:

| Connector | Connection asks for | Operations |
|---|---|---|
| ITGlueWarrantySync | API key, API host (`api.itglue.com` / `api.eu.itglue.com`) | List configurations, Update configuration |
| DattoRMMWarrantySync | Platform (e.g. `merlot`), API key, API secret | Get token, Get device, Set device warranty |
| AutotaskWarrantySync | API secret, API username, integration code | Get configuration item, Update configuration item (zone `webservices4`) |

- Connections for SharePoint and Office 365 Outlook
- Environment variables for the non-secret settings: Dry run, type/status IDs, myITProcess attribute,
  Max writes per run, Write Autotask, SharePoint site/list, summary recipient

Steps:
1. Create the state list: `.\New-WarrantySyncStateList.ps1 -SiteUrl https://<tenant>.sharepoint.com/sites/<site>`
2. make.powerapps.com → Solutions → **Import solution** → pick the zip.
3. Create the five connections when prompted (credentials go here), fill the environment variables.
4. Turn the flow on. It runs 01:00 UK time with `Dry run` = Yes; follow the rollout in the plan.

Notes
- Secrets entered on a connection are stored encrypted by the platform, can't be read back, and are never shown in
  run history. Datto's token is fetched per run; that action has secure inputs/outputs.
- Datto RMM tokens use a password grant, which custom connectors can't do natively. The connector's *Get token*
  operation adds `grant_type`, `username` (API key) and `password` (API secret) as query parameters from the
  connection. Test it first (*Test* tab on the connector, or run the flow in dry run); if Datto rejects query
  parameters, tell me and I'll switch it.
- These connectors are separate from the aBILLity solution's Autotask connector, so importing this cannot change it.
- The package layout mirrors a solution exported from the same environment (publisher `DefaultPublisherorgda80817a`,
  prefix `new`).
- Status is stored as `Glue later – review` (en dash), matching the list choice created by the script.

## Single-system flows: Autotask Only and Datto RMM Only

Two flows that each update **one system only**. They read IT Glue and apply the same date rules as the nightly
flow. Each then reads the device in its system and writes the warranty date only where that system differs.
Neither writes to any other system or uses the SharePoint state list, so both are safe to run at any time, for
example to backfill one system or recheck it.

| Flow | Devices it handles | Reads | Writes |
|---|---|---|---|
| Warranty Sync - Autotask Only | IT Glue `psa-id` set | `GET /ConfigurationItems/{psa-id}` → `warrantyExpirationDate` | `PATCH /ConfigurationItems` |
| Warranty Sync - Datto RMM Only | IT Glue `rmm-id` set | `GET /api/v2/device/{rmm-id}` → `warrantyDate` | `POST /api/v2/device/{rmm-id}/warranty` |

- Trigger: **manual** (Run button). Two inputs when you press Run:
  - **Device (blank = all)**: target one device by IT Glue configuration ID, the system's ID (`psa-id` /
    `rmm-id`), serial number or device name (not case-sensitive). Leave blank to process every device.
  - **Write now (ignore Dry run)**: *Yes* writes on this run even while the `Dry run` variable is Yes.
    Useful for piloting single devices without switching the nightly flow live.
- A targeted device is always reported in the summary: *Updated*, *Would update*, *Already correct*, *Error*,
  or a note that nothing in IT Glue matched, or that the device has no ID for that system or no warranty date.
- To schedule one, swap the trigger for a Recurrence (the inputs then default to all devices, no override).
- Uses the same environment variables: `Dry run` (when Yes it reports *Would update* and writes nothing),
  type/status IDs, myITProcess attribute, `Max writes per run`, summary recipient.
- Emails a summary with a table of every device whose date differed in that system and what happened
  (*Updated*, *Would update*, *Error*, *… lookup failed*).
- Runs one device at a time (each device is one read and at most one write), so a full first pass of
  1,500 devices takes a while. The Datto RMM Only flow fetches a Datto token at the start of every run, including
  dry runs, because it needs it to read devices. Before a big Datto run, check your API headroom with Postman
  request 2.6 (`/api/v2/system/request_rate`).
- If you use the Autotask Only flow for Autotask, set `Write Autotask` to No so the nightly flow doesn't also
  write it. The nightly flow always writes Datto RMM when it's live; the Datto RMM Only flow is for backfills,
  rechecks and single devices.

## Warranty Sync - List Devices

A read-only flow for finding a device to test on. It reads every active laptop and desktop from IT Glue,
applies the sync's date rules, and emails you the list. It writes nothing anywhere, so Dry run doesn't apply.

- Run inputs:
  - **Search (blank = all)**: text to look for in organisation, device name, serial, IT Glue ID, rmm-id or psa-id.
  - **Test-ready only**: *Yes* lists only devices with an rmm-id, a psa-id and a myITProcess date, which can be
    tested in every flow.
- The email has a table (first 300 matches) and an `itglue-devices.csv` attachment with every match. Columns:
  Organisation, Device, Serial, ITGlueID, RmmId, PsaId, ITGlueDate, MyITPDate, SyncDate (the date the sync would
  set) and Notes (no rmm-id / no psa-id / no myITProcess date / IT Glue later - review / IT Glue date will change /
  test-ready).
- Copy a device's ITGlueID, RmmId, PsaId, serial or name into the **Device** input of the Autotask Only or Datto
  RMM Only flow.

## Dry run and Write Autotask are Yes/No variables

From 1.0.0.6 `Dry run` and `Write Autotask` are Boolean (Yes/No) environment variables, defaulting to Yes. Set
`Dry run` to **No** to go live. The flows also accept the text values true/false/yes/no, so an older text
variable keeps working. If the import says the variable type can't change, delete `new_DryRun` and
`new_WriteAutotask` from the environment and import again.

## Removing leftover environment variables

The solution has 10 environment variables, none of them credentials. Earlier versions (1.0.0.0) also had
credential and URL variables. Importing an unmanaged solution never deletes components that a newer version
dropped, so if you imported 1.0.0.0 you need to delete these by hand. Go to **Solutions → Warranty Sync →
Environment variables**, select each one and choose **Delete from this environment**:

`new_ITGlueBaseUri`, `new_ITGlueApiKey`, `new_DattoApiUrl`, `new_DattoApiKey`, `new_DattoApiSecret`,
`new_AutotaskBaseUri`, `new_AutotaskUsername`, `new_AutotaskSecret`, `new_AutotaskIntegrationCode`

Those credentials now live only in the three connector connections.
